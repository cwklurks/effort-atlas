## Operational gates and batching

**Request unit (modify D12 — main operational disagreement).** Freeze **individual calls** as the request unit for every route, now, rather than "prefer `num_samples` batching if smoke passes, else omit the route." Reasons: (1) the priority order puts reliable collection above speed, and individual calls give per-row receipts, native usage, termination reason, and a per-call seed with no per-sample attribution ambiguity — safeguard 5 is trivially satisfied; (2) the batching path's failure mode under the document's own rule is severe — losing an entire panel because a billing-attribution semantic failed smoke — while individual calls cannot fail that way; (3) the proven SDK 0.25.0 resubmission defect lives in the sampling path; the one-submission wrapper is simpler to build and audit for single calls; (4) the conservative cost bound already assumes per-call prompt billing, so individual calls cost no more than the planning maximum (batching's shared prefill would only make realized cost cheaper than bound — a safe direction, but not one worth the attribution risk). To be explicit about what this does **not** do (per Codex audit, adopted): individual calls do not fix the 429-resubmission defect, and they multiply the number of billed submissions traversing the defective sampling path — so the per-call one-submission guarantee becomes *more* load-bearing, not less. Freezing the unit is a design decision; activation stays blocked for any unit until a supported one-submission client path passes independent review.
