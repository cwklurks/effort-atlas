Two-minute explanation

I built the benchmark table you asked for. All five public archives let us see whether a model got each question right. The four MathArena sets give us 123 math questions and output-token counts. HELM gives us 446 science questions answered by the same three archived models.

The limitation is that token exhaustion is not measured the same way. MathArena does not publish the requested cap or the reason a response stopped, so it can only suggest truncation. HELM is stronger for one model: Gemini has 42 responses explicitly labeled as stopping for length, and all 42 were scored wrong. But HELM's token fields are not comparable across providers.

So the public data can show the pattern and help us plan. It cannot tell us what a cut-off response would have answered with more room. That is why we still need the controlled experiment with fixed prompts, known limits, recorded stop reasons, and repeats.

Questions for Chirag

  1. Use all 123 MathArena questions for the descriptive section, but a smaller fixed set for the controlled experiment?
  2. Exclude HMMT-2026 item 25 from historical cross-model comparisons, or report its two versions separately?
  3. Include items 31 to 33 as MathArena source items with the provenance caveat?
  4. Keep effort by allowance as primary and cross-model matched-performance comparisons as secondary?
  5. Rerun power analysis with verified counts and real response-length data before fixing caps and repeats?

Recommended position

Use the public archives as descriptive evidence and planning data. Use the controlled experiment for causal claims. Keep token comparisons within a pinned route unless accounting units are proved comparable. Start the controlled math panel from HMMT 2025, then add HMMT 2026 only with explicit rules for item 25 and items 31 to 33.
